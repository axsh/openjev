# Philosophy: Agentic System as Code

## 1. ビジョン (Vision)

本プロジェクトは、エージェント（AI）を用いたシステム開発において、**「Agentic System as Code」** というパラダイムを提唱します。

AI への指示（プロンプト）や実行環境の設定は、これまで「非構造的なテキスト」や「その場限りのデータ」として扱われがちでした。しかし、複雑な自律型システム（Agentic System）においては、これらの要素こそがシステムの挙動を決定する重要な「ロジック」です。

私たちは、これらを TypeScript による厳密なコードとして記述し、管理することで、従来のプログラムコードが持つ**「型（Type）」**と**「関連性（Relationship）」**の恩恵をエージェントの世界に持ち込みます。

## 2. コア・原則 (Core Principles)

### 2.1 構造化された指示 (Structured Instructions)
プロンプトは単なるマークダウンではなく、他のプロシージャやツールとの依存関係を持つ「ソースコード」です。DSL を通じて記述することで、プロンプト間のリンクや呼び出し構造を静的に解析可能にします。

### 2.2 型安全な構成 (Type-Safe Configuration)
エージェントの実行環境（デプロイメント設定）は、型定義されたインターフェースを通じて構築されるべきです。これにより、設定ミスをコンパイルタイム（DSL ビルド時）に検出し、意図しない挙動を防ぎます。同時に、Agent の進化に追従するための拡張性（エスケープハッチ）も保持します。

### 2.3 システムの統合俯瞰 (Unified System View)
従来の命令的プログラム制御（Traditional Control）と、エージェントによる自律的実行（Agentic Execution）を同一の DSL 上で統合します。これにより、システム全体のデータフローと制御構造を、単一のコードベースから俯瞰し、管理することを可能にします。

### 2.4 指示書はロジックである (Prompt as Logic)
マークダウンで記述された指示書は、システムの実行時に解釈される「実行バイナリ」に近い存在です。コードで管理することで、バージョン管理、テスト、リファクタリングといったソフトウェアエンジニアリングのベストプラクティスをプロンプト開発に適用します。

### 2.5 設計図と具現化 (Blueprint and Materialization)
DSL 上での定義はシステムの「論理設計図（Blueprint）」です。「デプロイメント」とは、この設計図を、特定のエージェント（Claude Code や Codex 等）が最適に動作できる「物理的な環境構造（Materialization）」へと具現化する行為です。関連するスキル（Capability）、ルール（Policy）、依存する手続きを、エージェント固有の作法に従ってディレクトリやファイルへと適切にマッピングします。

### 2.6 ラッパースクリプトによるカプセル化 (Encapsulation via Wrapper Scripts)
エージェントが外部関数（fn）や他のプロシージャを呼び出す際、プロンプト内に複雑なコマンドラインを直接露出させるべきではありません。呼び出しロジックはデプロイ時にシェルスクリプト等にラッピングして書き出し、エージェントにはそのスクリプトを実行させるべきです。これにより、プロンプトの肥大化を防ぎ、将来的な引数の複雑化やデータ連携の変更に対して、エージェント側の指示（コード）を変更せずに対応できる「カプセル化」を実現します。

## 3. 目標 (Goals)

私たちは、AI が複雑なタスクをこなすための「知能」を、場当たり的なプロンプトエンジニアリングから、予測可能で管理可能な「ソフトウェア・エンジニアリング」へと昇華させることを目指します。
